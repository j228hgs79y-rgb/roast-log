# Roast Log — 個人烘焙紀錄工具

**版本：1.1 黑白灰介面更新（待實際 iPhone Safari 驗收）**

這是一套單人使用、iPhone 優先的離線 PWA。所有日常紀錄都保存在**目前開啟 App 的裝置的 IndexedDB**，無會員帳號、無伺服器端資料庫、無訂閱費。網頁程式本身需要一個 HTTPS 靜態網站網址；程式檔與個人紀錄是兩件不同的東西。

## 已實作

- 新增烘焙批次：咖啡品項、日期時間、生豆投入批次與重量；可只建立基本資料、日後補登。
- 烘焙計時：按「入豆」開始、按回溫／140°C／155°C／一爆／瓦斯／風門／抽樣／其他／下豆按鈕立即記錄時間。事件中的豆溫、壓力、風門及文字可以稍後補上。
- 中斷恢復：烘焙中的批次與入豆時間持久保存；重新打開時自動進入未完成批次，按原始開始時間繼續顯示經過時間；已儲存的事件不會重置。
- 批次詳情：原料、下豆結果、失重率、發展時間與 DTR（缺資料時不推算）；事件時間軸；多次個人杯測／沖煮測試；多筆客戶或同仁回饋；可上傳照片。
- 搜尋：批次編號、品項、生豆批次、觀察、測試與回饋全文搜尋，以及日期、狀態篩選。
- 即時保存：點擊事件時立即提交 IndexedDB；文字輸入短暫停頓或離開欄位後自動儲存；畫面顯示儲存狀態。
- 備份：完整資料（包含照片）匯出 ZIP。iPhone 優先嘗試系統分享介面，必要時退回 ZIP 下載。可由使用者存入 iCloud Drive。
- 還原：選擇完整備份 ZIP，驗證資料與附件後，經雙重確認才取代本機資料。
- 封存：列出三個月前的已結束批次、匯出封存 ZIP；須重新選取已存好的 ZIP 驗證與當前資料相同後，才可執行本機清理。舊 ZIP 可唯讀查閱。

## 安裝／部署（不需要安裝 Node 或購買網域）

### 建議：GitHub Pages（免費靜態託管）

1. 在自己的 GitHub 帳號建立一個公開 Repository，例如 `roast-log`。
2. 將本資料夾**所有檔案及子資料夾**上傳至 Repository 根目錄，保留檔案結構。
3. Repository → Settings → Pages → Build and deployment → Deploy from a branch，選 `main`／`/ (root)`，儲存。
4. GitHub 顯示部署完成後，用 **iPhone Safari** 開啟 Pages 提供的 HTTPS 網址。
5. Safari 分享選單 → **加入主畫面**。往後從主畫面開啟 Roast Log。
6. 第一次開啟時保持網路連線，待程式資源載入快取；之後可測試飛航模式使用。

**注意**：公開的 GitHub Repository 只有 App 程式碼；你的烘焙資料不會上傳到 Repository，而是留在 iPhone 的瀏覽器儲存空間。不要把備份 ZIP 上傳至公開 Repository。

如果已經有你自己控制的 HTTPS 靜態站，也可以使用相同的檔案。**部署網址應長期固定**，因為改網址會改變 IndexedDB 的儲存來源。

### 本機開發

在有 Python 3 的電腦執行：

```bash
cd roast-log
python3 -m http.server 8000
```

電腦瀏覽器開啟 `http://localhost:8000` 測試。手機應使用已部署的 HTTPS 網址；不要直接以 `file://` 開啟，因為 PWA／離線快取等功能需要安全的網頁來源。

## 日常使用

1. 「開始新的一鍋」填品項、可選填生豆批次／重量；直接入豆開始計時。
2. 到重要節點時按一下事件鍵；點擊時的時間立即保存，數值可以之後補填。
3. 按「下豆結束」，在批次詳情補上熟豆重量、下豆判斷及色度等。
4. 從該批次的「測試」及「回饋」頁籤持續新增紀錄。
5. 每次烘焙完成後，按「已完成 · 備份到 iCloud」，於分享介面選「儲存到檔案」→ iCloud Drive。資料管理頁可備份整個資料庫。
6. 刪除舊資料前，先完成封存、將 ZIP 寫入 iCloud、再重新選取該 ZIP 通過驗證，才能刪除。

## 資料可靠性與限制

- 點擊事件後看到「本機已儲存」才代表該事件已寫入 IndexedDB。若輸入文字後立即關閉，最後未完成寫入的幾個字仍可能遺失。切換背景時也會嘗試保存。
- **iCloud Drive 不會自動同步**。iPhone 本機資料與 ZIP 備份是不同副本。Safari 清除網站資料、移除 App、換機或手機故障時，可能失去尚未備份的資料。
- 一般 iPhone PWA 無法不經操作就持續寫入 iCloud Drive。分享／下載完仍需在 iCloud Drive 內完成保存。畫面只記錄使用者自己確認過的備份時間，不會假裝偵測到真正的 iCloud 寫入成功。
- 每次完整還原會**覆蓋**本機整套資料，不提供跨裝置自動合併。
- 只有稀疏溫度事件時，不會虛構連續烘焙曲線或 RoR。
- 本程式是第一版：已通過程式語法與 ZIP 資料往返測試，但此環境的瀏覽器受到限制，**尚未在真實 iPhone Safari 測過中斷恢復、檔案分享及離線切換**。正式使用前先按下方檢核表測試幾個示例批次。

## 專案檔案

- `index.html` — 入口頁
- `styles.css` — iPhone 優先響應式介面
- `app.js` — 操作介面及業務流程
- `db.js` — IndexedDB 存取與交易
- `archive.js` — ZIP 備份、驗證、還原、封存
- `sw.js` — 離線快取
- `manifest.webmanifest`、`icons/` — 加入主畫面設定
- `vendor/jszip.min.js` — 隨專案附帶的 JSZip；見 `vendor/JSZIP-LICENSE.md`
